## Continuation record — sync protection for .musicsyncrename/ recovery data (2026-10-18, V10 mission)

### Defect and fix
Production defect reported by user: after Bulk Rename creates `<library>/.musicsyncrename/` (backup MP3s + `.jsonl` session journals), MusicSync sync previews proposed copying that recovery data to the phone. Root causes found and fixed at source level:
1. **Inventory/rsync used only `settings.exclusions`.** Pre-existing user settings.json files contain just `["/.thumbnails/"]`, so a root-level `.musicsyncrename/` was inventoried, mapped for Android destinations, proposed in dry-run previews, copied by real rsync (update and mirror), and orphaned phone-side copies were exposed to `--delete-after`. Fix: mandatory protected-root merging at the two choke points — new `PROTECTED_ROOTS = ("/.musicsyncrename/",)` + `sync_exclusions()` in `settings.py`, applied inside `filesystem.inventory()` (covers PC source inventory, destination filename map, phone-side inventory, snapshot/digest consistency) and `rsync.arguments()` (covers dry-run preview, real transfer, mirror deletion — excluded paths are never deleted without the absent `--delete-excluded`). Root-anchored semantics: an album's own `.musicsyncrename/` subdirectory remains ordinary content. Old settings JSONs stay loadable (protection is enforced below the config layer, so nothing in saved configs can lose it).
2. **ReplayGain could alter recovery backups.** `rsgain easy <source>` recursively scans the raw library root and rsgain 3.6 has no exclusion option; demonstrated pre-patch that a backup MP3 inside `.musicsyncrename/backups/` got ReplayGain TXXX tags written (bytes altered). Fix: new `filesystem.replaygain_stage(source, inventory)` context manager — temporary symlink tree of every ordinary top-level entry (loose files AND album dirs) from the fresh source inventory; `workflow._core` now runs `rsgain easy` over that stage (`replaygain.command(settings, scan_root=stage)`), verified empirically that rsgain follows symlinked dirs/files and writes tags back through them. Ordinary content is tagged exactly as before; recovery data is never visible to the tool.

Changed files (committed): `src/musicsync/settings.py`, `src/musicsync/backend/filesystem.py`, `src/musicsync/backend/rsync.py`, `src/musicsync/backend/replaygain.py`, `src/musicsync/backend/workflow.py`, `src/musicsync/main_window.py` ("Ignored and protected:" label now shows effective protection), new `tests/test_rename_sync_exclusion.py`.
